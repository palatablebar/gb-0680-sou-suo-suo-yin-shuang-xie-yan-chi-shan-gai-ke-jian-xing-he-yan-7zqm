# 双写定义

event_id唯一，doc_id文本保留。side为source或index；版本正整数按Decimal比较并作为文本序列化。upsert要求JSON对象，delete忽略payload并产生墓碑。相同文档同端同版本不同内容全部隔离，存在未裁决冲突的主体不回落旧版本；同内容合并来源；较高版本覆盖低版本，迟到旧写不得覆盖墓碑。

双端最终版本、操作、文档分别核验。目标缺失、删除未确认、索引领先、陈旧索引、内容差异分开展示。source_time与visible_time带偏移；可见延迟按实际秒数。默认阈值120秒，等于阈值通过。已可见但超过阈值为延迟，尚无目标且等待时间超过阈值为缺失，等待中不冒充延迟。

对账expected=每文档应通过的1，reported=门禁通过1或未通过0，逐条保存visibility_state和gate原因，允许按文档复核。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

## 核验窗口

归窗口径固定为 `observable-settlement-v1`，实现见 `app/windows.py`，业务日时区取参数 `window_timezone`（默认环境变量 `WINDOW_TIMEZONE`，未设置时用 Asia/Shanghai）。

- 以文档为单位归窗。每篇文档取它全部有效事件（含被高版本替代的事件、两端事件）的可观测时刻；有 `visible_time` 用可见时刻，否则用 `source_time`。最晚的可观测时刻所在业务日即该文档的核验窗口。
- 昨夜发生、今晨才可见的文档因此归入可见当日，不会按发生日漏掉结论。今天发生却补进昨天复核批的文档，仍按它自己的可观测时刻归窗，不按文件到达日。
- 迟到旧事件不会在到达日重新计入：它的业务日由自身时间戳决定，与批次文件何时到达无关。
- 每篇文档只归一个窗口，文档内所有事件随文档走；每个事件只归属其自身业务日一个窗口。因此同一事件不会跨窗重复计入。
- 每篇文档保留归窗依据：`window_basis`（`可观测字段:数据端:事件号@结算时刻`）、`window_settlement_at`、`window_event_windows`（事件业务日）、`window_events`（逐事件的可观测字段、时刻、业务日与源行号）、`window_sources`（源行号），均可追回。
- `window_timezone` 是口径的一部分，会写入参数并参与批次摘要。同一输入同一参数必得同一批次窗口；重跑同一批不新增窗口、结论不变。改动时区会得到新批次，不会覆盖旧结论。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。归档只能封存窗口自洽的批次：同一文档或事件跨窗重复、文档窗口与其事件业务日不一致、存在未归窗文档时分别返回 `WINDOW_SPLIT`/`WINDOW_MISSING`。
